# New API BOV（商业化运营版）产品定义文档

> **BOV = Business Operation Version**。本文档是 `new-api-bov` 项目的顶层产品定义，界定项目定位、功能模块边界、许可与启动机制及演进路线。所有后续需求文档、设计文档均以本文为基准展开。

---

## 1. 项目定位

**New API BOV 是基于开源项目 New API 二次开发的商业化运营版本**，在保留原有大模型网关与 AI 资产管理能力（多渠道接入、令牌计费、用户管理、渠道负载均衡等）的基础上，面向**需要合规运营、对外收费服务**的场景，新增四大能力域：

| 能力域 | 解决的问题 |
| --- | --- |
| **合规身份体系**（个人实名 / 单位实名） | 满足生成式 AI 服务面向公众提供时的实名制监管要求 |
| **商业化财务体系**（财务工作台 / 发票） | 支撑充值、对账、退款、开票的完整资金闭环 |
| **数据安全网关**（脱敏网关） | 请求进入上游大模型前对敏感信息（PII）脱敏，防止数据出域 |
| **会话知识库** | 用户按需为会话挂载私有知识，实现按需启停的 RAG 增强 |

同时，系统**内嵌许可证 SDK**：私有化部署必须完成「基础承诺确认 → 申请免费授权 → 导入激活」后方可登录启用，形成可控的分发与合规确认链路。

### 与上游的关系

- 保留与上游 `QuantumNous/new-api` 的合并能力：商业功能一律以**独立模块**（新目录 + 功能开关）实现，不侵入上游核心逻辑，降低长期同步成本。
- 仓库地址：`https://github.com/zhongxinxuhk/new-api-bov`；镜像：`ghcr.io/zhongxinxuhk/new-api-bov`。

## 2. 模块总览与功能开关

| 模块 | 目录约定（草案） | 开关粒度 | 默认状态 |
| --- | --- | --- | --- |
| 许可证 SDK / 启动向导 | `license/` | 强制启用，不可关闭 | 恒开 |
| 用户实名认证 | `module/kyc/` | 系统 | 开 |
| 单位实名认证 | `module/kyc/`（org 子域） | 系统 | 开 |
| 财务工作台 | `module/finance/` | 系统 | 开 |
| 发票管理 | `module/invoice/` | 系统 | 开 |
| 脱敏网关 | `module/maskgateway/` | 系统 → 渠道 → 令牌 | 关 |
| 会话知识库 | `module/knowledge/` | 系统 → 用户 → 会话 | 关 |

> 设计原则：**合规类模块（实名、财务、发票、许可证）为运营版主体，恒开**；**增值类模块（脱敏网关、知识库）按需选择启用或禁用**，开关从系统级向下逐级覆盖。

## 3. 功能需求定义

### 3.1 用户实名认证（个人 KYC）

- **目标**：未完成实名的用户不可充值、不可创建生产用令牌、不可调用计费接口（可浏览与配置，满足"先实名后服务"的合规基线）。
- **认证方式**（预留服务商适配接口，阶段一支持二要素）：
  - 二要素：姓名 + 身份证号（公安核验）；
  - 三要素：+ 手机号运营商核验；
  - 可选扩展：人脸活体检测。
- **实名等级**：`L0 未实名` → `L1 二要素` → `L2 三要素` → `L3 活体`。等级与充值限额、并发限额、可用模型范围联动（限额策略由运营方配置）。
- **信息存储**：身份证号等敏感字段**加密存储**（独立密钥），展示端全链路脱敏（如 `330***********1234`）；审计日志不落明文。
- **审核流**：机器核验通过即生效；核验失败走人工复核队列（复用管理员后台）。

### 3.2 单位实名认证（企业 / 组织认证）

- **申请材料**：单位名称、统一社会信用代码、营业执照照片、法定代表人信息、经办人信息及授权委托书。
- **核验方式**（预留适配）：企业工商四要素接口核验；对公打款小额验证（可选）；人工审核兜底。
- **认证结果**：单位主体通过后，其名下用户可绑定到该单位（多成员、单位管理员角色），享受单位级额度、单位抬头开票、单位级脱敏策略。
- **状态机**：`草稿 → 待审核 → 核验中 → 已认证 / 已驳回 → 已注销`；驳回须记录原因并可重新提交。

### 3.3 财务工作台

面向运营方财务角色的统一资金操作界面：

- **充值管理**：在线支付对账（复用易支付/微信/支付宝等现有通道）、人工补单、充值优惠配置。
- **资金流水**：每笔充值、消费、退款、调账生成不可篡改流水记录（append-only），支持按用户/单位/时间段/类型多维检索与导出。
- **退款管理**：申请 → 财务审核 → 原路退回；退款自动扣减对应额度并联动发票红冲提示。
- **调账与坏账**：管理员调账须双人复核（可配置），留痕审批单。
- **对账单**：按自然月生成用户/单位账单，作为开票依据；支持导出 CSV / Excel。
- **角色**：财务专员（操作）、财务主管（审核）、审计（只读）。

### 3.4 发票管理

- **发票类型**：电子增值税普通发票、电子增值税专用发票（阶段二）。
- **抬头管理**：用户端维护个人抬头 / 单位抬头；**单位抬头必须在对应单位通过实名认证后方可使用**。
- **开票流程**：
  ```text
  用户选择账单/充值记录 → 填写抬头 → 提交开票申请
    → 财务审核 → 第三方开票服务商开票（适配层：诺诺/百望等，接口预留）
    → 状态回传 → 版式文件交付（邮件 + 站内下载）
  ```
- **红冲与换开**：支持全额红冲、重新开票；红冲与退款联动校验。
- **限额控制**：按实名等级与运营方风控配置单张/月度开票限额。
- **状态机**：`待审核 → 开票中 → 已开票 → 已交付 → 已红冲`；异常态 `开票失败`（可重试）。

### 3.5 脱敏网关（Mask Gateway）

- **定位**：位于中继链路（relay）前置的可插拔过滤器，对请求体（及可选响应体）中的敏感信息做改写后再转发上游。
- **内置规则集**：中国大陆手机号、身份证号、银行卡号、邮箱、IP 地址、姓名（结合上下文词典）等，规则可独立启停。
- **自定义能力**：正则规则、敏感词典、外部检测 API（预留）。
- **改写策略**：`掩码（mask）`、`替换（replace）`、`哈希（hash）`、`可逆令牌化（tokenize + 响应回填还原，密钥托管于服务端 KMS）`。
- **生效粒度**：系统级总开关 → 渠道级策略 → 令牌级策略，逐级覆盖；模型白名单可豁免（如本地化部署模型可关闭脱敏）。
- **审计**：命中规则、改写字段计数记入审计日志，**不记录原文**。

### 3.6 会话知识库（按需启停）

- **核心要求**：用户可以**按需选择启用或禁用**某个会话的知识库增强，默认关闭；系统级也可由管理员整体停用。
- **能力**：
  - 文档管理：上传 PDF / DOCX / TXT / MD / 网页 URL，切片、向量化（嵌入模型可配置，走现有渠道体系计费）；
  - 知识库实例：归属于用户或单位（单位库共享成员可见）；
  - 会话挂载：对话页可选「启用知识库」并选择 0~N 个库，检索召回片段注入上下文（可调 top-k、相似度阈值）；
  - 生命周期：删除知识库级联清理向量与文件；重索引任务异步执行（复用现有异步任务框架）。
- **向量存储**：阶段一采用 PostgreSQL（pgvector）以贴合现有三数据库兼容基线的最低复杂度，预留 Milvus 等独立向量库适配接口。
- **计费**：索引与检索消耗按现有 token 计费体系计量（嵌入/重排模型计费），知识库存储容量可配置配额。

### 3.7 许可证 SDK 与私有化启动流程

**强制门槛**：私有化部署在完成以下流程前，系统处于「未激活态」——所有登录入口关闭，仅暴露启动向导与激活接口。

```text
首次启动
  → ① 基础承诺确认：管理员阅读并勾选《合规使用承诺》
      （合法用途、数据合规、不得绕过许可等，勾选记录落审计）
  → ② 生成机器指纹：对硬件/实例特征（CPU、MAC、实例 ID 等）
      做单向哈希，形成 fingerprint
  → ③ 申请免费授权：
      在线方式：向授权服务门户提交指纹 + 用途申明，自动/人工签发
      离线方式：导出申请文件 → 发给授权方 → 取回 license 文件
  → ④ 导入授权并激活：SDK 验证签名（Ed25519）、有效期、
      指纹绑定、模块授权范围 → 激活成功
  → ⑤ 开放登录与正常使用
```

- **License 文件内容**（JSON + Ed25519 签名）：`license_id`、` licensee（被授权主体）`、`fingerprint`、`issued_at / expires_at`、`module_scope（授权模块集合）`、`instance_limits（用户数/渠道数等上限）`、`plan（free / trial / commercial，当前主推 free）`。
- **运行期校验**：进程启动时校验签名与有效期；到期前 30/7/1 天站内提醒；过期后进入**宽限期（默认 7 天，只读告警）**，宽限期后回落未激活态。
- **授权变更**：换机/扩容需重新申请，旧授权由授权方吊销（CRL 或在线吊销列表查询，离线部署允许宽限）。
- **SDK 形态**：Go 侧 `license/` 包（校验、指纹、启停门禁中间件）+ 授权门户适配层（阶段一可用人工邮件签发 + 命令行签发工具）。

## 7. 里程碑规划（建议）

| 阶段 | 内容 | 交付判据 |
| --- | --- | --- |
| **M1 许可证地基** | license SDK、机器指纹、承诺确认向导、免费授权签发工具（CLI）、**未激活全锁门禁** | 未激活实例登录与 API 调用全拒、仅开放启动向导；导入 license 后正常使用；三数据库迁移通过 |
| **M2 合规身份** | 个人二要素实名 + 单位实名 + 审核工作流 + 实名等级与调用/充值门禁 | 未实名用户无法充值与调用；服务商适配接口可替换 |
| **M3 财务与发票** | 资金流水、退款、对账单、抬头、开票申请与状态机、服务商适配层 | 一次完整「充值→消费→对账→开票→交付」闭环 |
| **M4 脱敏网关** | 规则引擎、策略分级、可逆令牌化、审计 | 命中样例请求在上游侧不可见 PII，响应回填正确 |
| **M5 会话知识库** | 文档管理、pgvector 索引、会话级启停、检索注入 | 用户可在会话中按需启停知识库并正确召回 |

## 8. 已确认决策（Concluded Decisions）

> 以下为已拍板、进入实现/不会回退的产品决策（区别于第 9 章仍待定的未决问题）。

| 决策 | 结论 | 影响 |
| --- | --- | --- |
| 未激活实例门禁 | **登录 + API 调用全锁**：系统进入维护态，仅开放启动向导（承诺确认 + 导入授权）；激活后恢复 | M1 中间件需拦截登录与业务 API，放行 `/api/setup`、公开健康检查等白名单 |
| Ed25519 公钥托管 | **证书生成器 + 配置指定**：签发工具生成私钥/公钥；运行期经 env/config 注入公钥做签名校验；不硬编码、可轮换 | 新增 `license/` 签名校验只依赖注入公钥；签发私钥仅存授权方 |
| 免费授权形态 | 免费授权（free plan）作为第一优先级；Commercial/Trial 后续 | license 字段 `plan` 预留 |
| 仓库与镜像 | 代码 `zhongxinxuhk/new-api-bov`；镜像 `ghcr.io/zhongxinxuhk/new-api-bov` | 已生效 |
| Go 模块路径 | `github.com/zhongxinxuhk/new-api-bov`（已从 QuantumNous 迁移） | 已生效 |

## 9. 未决问题（待产品决策）

1. **实名/开票服务商选型**：二要素核验与电子发票服务商（诺诺、百望、航信等）的商务与接口确认。
2. **授权门户形态**：免费授权阶段是否自建 Web 门户，或采用「CLI 签发 + 邮件回传」的轻量方案。
3. **可逆令牌化的密钥托管**：自建 KMS / 环境变量派生 / 第三方 KMS 的取舍。
4. **脱敏与计费的交互**：脱敏改写后 token 计量以改写前后哪一侧为准（建议：按实际上游用量）。
5. **上游同步策略**：商业模块目录隔离下，多久同步一次上游及冲突处理流程。
6. **知识库配额商业化**：免费配额与付费扩容的定价维度（存储 / 索引次数 / 检索次数）。

## 10. 合规与安全基线（贯穿性要求）

- 敏感字段（证件号、税号、银行账户）应用层加密存储 + 展示端脱敏 + 审计不留明文。
- 所有新增资金操作可审计、可追溯、append-only。
- 实名信息与第三方核验服务商的传输加密与个人信息处理告知（隐私政策更新）。
- 许可证私钥仅存在于授权签发方环境，被授权系统只内置公钥。
- 新增模块沿用项目既有质量门禁：`vue-tsc --noEmit`、三数据库迁移验证、`relaykit` 独立构建不受影响。
